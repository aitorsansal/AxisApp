Fix these first

  1. Android drops the "." decimal separator. Typing 8.50 saves 850 €, a 100× error with no warning (A1).
  2. "Saldar" settles a whole debt in one tap, on both clients. There's no confirmation, no amount choice and no undo. The next row slides under your finger, so two quick taps settled Bruno and Ana on Android (W4, A2).
  3. The web date field accepts impossible dates. On the event form this throws an uncaught RangeError and leaves the form stuck on "Guardando…". On the expense form 31/02/2026 is silently saved as 3 March (W1, W2).
  4. The ICS calendar feed emits invalid timestamps (20261029T200000+0000Z), so strict calendar clients may drop or misplace every event (W3).
  5. The web creates rent/utilities expenses that Android can't label. Android Stats shows the raw key Category_rent (W5, A3).

Findings

A1HighAndroid

A dot decimal is silently dropped: "8.50" becomes 850 €

Repro
Mixed group → + → amount field empty → type 8.50. The field shows 850 and shares 425,00 / 425,00. Typing 8,50 works. Typing into the field while it showed "0,00" produced 0,85000.
Why it matters
A wrong amount by a factor of 100, with no validation. It's easy to hit with a keypad that shows ".", a hardware or Bluetooth keyboard, or a pasted amount.
Likely cause
AddExpenseViewModel.cs:665-667 says parsing accepts both "," and ".", but the "." never reaches the ViewModel. Android's numeric input filter for a Spanish locale most likely discards it before OnAmountTextChanged runs. Not verified in code.
Suggestion
Use a text keyboard with a custom filter that maps "." to ",", or a decimal InputType with a locale-agnostic DigitsKeyListener("0123456789.,"). Add an "amount looks unusually large" check on save.
W4 / A2HighWeb + Android

One-tap "Saldar" with no confirmation, amount choice or undo, and double-taps settle two people

Repro
Group with 2+ debts → tap "Saldar" on the first row. The row disappears and the next one moves up under the cursor or finger. A second tap 1.5 s later settled the next person too (reproduced on Android: Bruno €300 + Ana €306,78; also seen on web).
Code
Web GroupDetailPage.tsx:202-228 (handleSettle writes immediately). Android GroupExpensesViewModel.cs:407 (Settle).
Suggestion
Open a small sheet: "Bruno te paga 300,00 €" with an editable amount (partial settle-ups are common) and Confirm. At minimum add an undo snackbar and keep the list layout stable while saving.
W1HighWeb

Event form freezes on an invalid date: uncaught RangeError, stuck on "Guardando…"

Repro
Add event → click into the prefilled "Fecha de inicio" and type 28102026. The digits get inserted at the cursor, giving 27/21/0202. Press Guardar. The console shows RangeError: Invalid time value at combineToIso, and the button stays on "Guardando…" until reload.
Cause
DateField.tsx:17-22 only checks the dd/mm/yyyy shape, not whether the date exists. AddEventPage.tsx:84 compares two NaN dates, which passes, and combineToIso (:21-23) throws after setBusy(true).
Suggestion
Validate in displayToIso by round-tripping through Date and rejecting a mismatch. Show an inline error. Wrap submit in try/finally so busy always resets.
W2HighWeb

An impossible expense date is saved silently: 31/02/2026 becomes 3 March 2026

Repro
Add an expense from an event → set Fecha to 31022026 → save. The expense "Gasolina evento" now sits in March, on the wrong month in Stats and in the trend line on both clients.
Cause
Same DateField gap: JavaScript Date rolls Feb 31 over to Mar 3.
W3HighCalendar feed

The ICS feed writes invalid DTSTART/DTEND values

Evidence
DTSTART:20261029T200000+0000Z and DTEND:20261029T223000+0000Z. RFC 5545 UTC form is 20261029T200000Z. Only the 1-hour fallback DTEND comes out right.
Cause
supabase/functions/calendar-feed/index.ts:29-31: toIcsDate assumes an …sss Z ISO string, but PostgREST returns timestamptz as 2026-10-29T20:00:00+00:00. The fallback goes through toISOString(), which is why it's correct.
Fix
toIcsDate(new Date(event.starts_at).toISOString()). Also check whether VALARM TRIGGER:-P4D (a reminder 4 days before every event) is intended.
W5 / A3HighCross-client

The web offers "Alquiler"/"Suministros" for new expenses; Android has no labels or colours for them

Repro
On the web, create "Alquiler piso QA (categoria rent)" with category Alquiler. On Android, Stats shows the bar and legend label Category_rent, in the same blue as Comida. The Android editor highlights no chip, and the list shows a cart icon.
Cause
webapp/src/lib/types.ts:88-100 keeps the legacy keys "so existing expenses can be edited", but the same list feeds the picker for new expenses. AppConstants.cs:50 has 8 keys and there are no Category_rent/Category_utilities strings. stats.ts:33 also lacks them, so they fall back to palette slot 0 on the web too.
Good news
Android preserves the unknown key on save (AddExpenseViewModel.cs:445), so nothing is lost.
Suggestion
Show legacy keys only when the expense being edited already uses one. Add the two label strings to Android so existing data renders.
W6HighWeb

Whitespace-only group names are accepted

Repro
New group → name " " → Create. You get a group with an empty title and an empty sidebar entry.
Cause
NewGroupPage.tsx:23-26 sends name without trim(), and create_group() has no check. Rename does trim, which is how I fixed the name afterwards.
Suggestion
Trim on the client, and add check (length(btrim(name)) > 0) on groups.name.
W7 / A8MediumWeb + Android

The settlement editor reuses the full expense split UI

Web
Recipients are checkboxes. Picking two shows the raw server error "A settlement must have exactly one share". Buttons read "Guardar gasto"/"Eliminar gasto" under the title "Editar liquidación".
Android
It shows the equal/manual toggle, checkboxes and per-person amounts. With two recipients, "Guardar gasto" is disabled with no explanation, and the header "Guardar" silently does nothing.
Suggestion
A dedicated settlement form: from (payer), to (single choice), amount, date.
W8 / A7MediumCross-client

Settlement descriptions are shown differently on each client

Observed
I edited a settlement's description to "Bizum de Bruno". The web still shows "Saldar cuenta" (search for "bizum" finds it but displays "Saldar cuenta"). Android shows "Bizum de Bruno — Bruno Phantom pagó a Claude QA Bot".
Also
New settlements store the creator's localized label (description: t('GroupDetail_SettleUp'), GroupDetailPage.tsx:218). Android displays stored descriptions, so an English Android user sees "Saldar cuenta" for settlements a Spanish user made.
Suggestion
Store an empty description for auto-created settlements and localize at render time on both clients (Android already falls back at GroupExpensesViewModel.cs:209). Show a custom description on the web when one exists. Android's "X pagó a Y" subtitle is better than the web's "X pagó"; port it.
A5MediumCross-client

Android relative times are wrong for web-created expenses

Observed
Expenses I created on the web about an hour earlier show "hace 14h" on Android. The settlement made 25 minutes earlier still shows "ahora mismo".
Cause
The web stores date-only expenses at local midnight (webapp/src/lib/dates.ts:8), and Android's relative formatter treats occurred_at as a real moment. This also makes same-day ordering differ (settlements keep the exact time, so they sort above newer expenses).
Suggestion
Show occurred_at as a date ("hoy", "27 oct") rather than relative hours, or sort and label "recent" by created_at.
A4MediumAndroid

Every expense row uses the shopping-cart icon

Observed
Taxi (Transporte), Alquiler and Comida all show a cart. The web uses per-category icons (car, house, etc.), but its Food and Shopping share the cart (icons.ts:48,53).
Cause
Views/GroupExpensesView.xaml:138 and Pages/EventDetailPage.xaml:300 hardcode Icons.ShoppingCart.
A6MediumAndroid

Back from a deep-linked event lands in an unrelated group

Repro
With Claude QA open, run adb shell am start -d https://app.axisapp.aitorsansal.com/groups/<Mixed>/events/<id>. The event opens correctly, but Back goes to Claude QA, not Mixed Codex-Claude QA.
Suggestion
When handling a deep link, navigate to the group first and then push the event, e.g. //Groups/GroupDetail?id=…/EventDetail?id=….
W11MediumWeb

The selected group tab isn't in the URL

Observed
After creating an event you land on the Gastos tab and don't see it. Back from event detail or a reload also resets to Gastos.
Cause
GroupDetailPage.tsx:50 keeps the tab in useState. Use ?tab=events (search params) and have AddEvent return to it.
W10MediumWeb + Android

Editing an equal split always opens in Manual mode

Observed
An expense saved as "A partes iguales" reopens as Manual, even for an exact 300/300/300 split on Android. Changing the amount leaves the old shares in place ("Restante 9.99" error) until you click Equal again.
Suggestion
Intentional (AddExpensePage.tsx:62), but it could check whether the saved shares match equalSplitCents(total, ids) and open in Equal mode when they do.
W12MediumWeb

Raw English server and browser errors appear in the Spanish UI

Seen
"The source image could not be decoded." (non-image receipt), "numeric field overflow" (amount 99999999999), "A settlement must have exactly one share", "You're already in a group with this person, so this invite isn't for you", "Invalid invite code".
Cause
setError(error.message) pattern across pages (e.g. JoinGroupPage.tsx:37). Map known raise exception messages and error codes to t() keys, falling back to a generic localized message.
W13MediumWeb

Number inputs: the mouse wheel changes the amount, and decimal separators are mixed

Observed
With the amount focused, scrolling the page over it changed 25 to 24,99 silently. Share inputs show "3,34" (browser-locale rendering of type="number") while "Restante: 0.00 EUR" uses toFixed with a dot, and in the English UI shares still show "0,00".
Suggestion
Use type="text" inputMode="decimal" with your own parse and format (it also avoids the native spinner) and format all money through one locale-aware helper.
W14MediumWeb

No upper bound on amounts

Observed
99999999999 → raw "numeric field overflow"; share fields truncate the digits. Add a client-side maximum that matches the column's precision.
W16MediumWeb + Android

No visible edit history, although any member can edit any expense

Observed
I could open and edit Codex's "USD shared lunch". expense_history is recorded on every update and delete, but neither client has any UI for it, so nobody can see who changed an amount.
Suggestion
A small "Historial" link on the edit screen listing previous versions ("Codex cambió 20 → 25 USD"). This builds a lot of trust in a shared ledger.
W15MediumWeb

Event "Compartir" on desktop opens the native Windows share sheet with no fallback

Cause
EventDetailPage.tsx:156 prefers navigator.share, which desktop Chrome exposes. Most desktop users want "copy link". Offer both, or prefer the clipboard when (pointer: fine).
W17MediumWeb

Adding a phantom silently overwrites the clipboard and mints an invite

Observed
"Añadir" a phantom → notice "Nuevo enlace de invitación copiado". Every "Reenviar" creates another 7-day token, and old ones stay valid.
Suggestion
Don't create an invite until the user asks to share. Consider revoking older open tokens for the same phantom when a new one is created.

Smaller polish items

  • Enter doesn't submit "Añadir un miembro por nombre", because there's no <form> (MembersPage.tsx:239-280).
  • Category order puts "Otros" before "Alquiler"/"Suministros".
  • Accessibility: checkboxes are announced as "on", date fields as "dd/mm/yyyy" (label not associated), and share inputs only by member name.
  • Event-linked expense rows show "3/3/2026" while everything else uses "27 oct".
  • With the green accent, the balance gradient ends in mauve, and the dark "owes you" text has low contrast there.
  • Display name defaults to the email, which exposes it to every co-member ("claude@test.com pagó"). Consider defaulting to the email's local part, or asking for a name on first login.
  • The payer line says "<my name> pagó" rather than "Pagaste".
  • Native window.confirm/window.prompt are used for delete, leave, dissolve, rename and account deletion, which is inconsistent with the in-app Modal. Dissolving a group with others in it is a single native confirm.
  • Negative amount: browser validation blocks the save, but the share preview shows "-2,50".
  • Event location is plain text (no maps link). Expenses added from an event don't prefill the event title.
  • Terminology: "Saldar" (button) vs "Liquidar"/"liquidación" (profile copy, settlement editor title).
  • Renaming a member (alias) on the web means clicking the name, which nothing hints at. Android's pencil icon is much clearer.
