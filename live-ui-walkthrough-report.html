Back button invisible on Join Group / New Group pages

Fixed
JoinGroupPage.xaml · NewGroupPage.xaml

Only found by actually opening these pages — static review of the XAML alone wouldn't have caught it. Both pages had RowDefinitions="60,*" for the header row, but the header also carries a 40px top margin (added to clear Windows' native caption buttons) plus a 44px chevron — 84px of content squeezed into a 60px row. The chevron was pushed completely out of the visible area, so the only way back was the OS window's own back arrow, not anything the app drew.

Group Detail's page didn't have this problem because its header row was already 100,* from an earlier fix — I just hadn't matched that when I copied the same margin fix to the other two pages.

Fix: bumped both pages' header row from 60,* to 100,*, matching Group Detail. Verified the chevron renders and is tappable on both pages afterward.

Open — visual issue

"Join with code" / "+ New group" button pair reads as flat and mismatched

Not fixed — design call needed
GroupsPage.xaml, bottom-right corner of the groups list

"the join with code or + new group (as how I see them) they look super ugly"

Looking at it live, I agree this pairing is the weakest spot in the app right now. Two things are going on:

1. "Join with code" barely reads as a button. It uses BtnOutlinePrimary — transparent background, a 1px border in BtnOutlinePrimaryBorder (#3B4E85) against the page's near-black background (#0B1220). That border is low-contrast by design elsewhere in the app (it works fine on a solid `Surface` card), but floating alone over open background with no fill and no shadow, it just looks like a washed-out gray oval rather than a tappable control.

2. The two buttons don't share an elevation language. FabButtonStyle (used by "+ New group") carries a drop shadow — that's what makes a FAB read as floating above the content. The outline button next to it has no shadow at all, so one pill looks like it's floating and the other looks pasted flat onto the page. Sitting side by side, the mismatch is more noticeable than either button would be alone.

There's also a smaller code smell worth knowing about, though it's not visibly causing a problem right now: FabButtonStyle sets its own HorizontalOptions="End", VerticalOptions="End", and its own Margin="0,0,16,16" — all dead weight here, since the button already sits inside a HorizontalStackLayout that positions both buttons itself (and the XAML already overrides the margin back to "0" to compensate). It works today only because the override happens to cancel it out — fragile if either button's style changes later.

Options, roughly cheapest to most involved:
• Give "Join with code" a solid fill (e.g. SurfaceElevated) instead of transparent, so it reads as a real button without needing a shadow.
• Or add the same drop shadow to both, so they visually belong to the same floating group.
• Or split them apart entirely — keep "+ New group" as the one true FAB in the bottom-right corner, and move "Join with code" somewhere less prominent (e.g. next to "Your groups" header, or only shown in the empty-state).
This is a design-language decision more than a bug fix, so I didn't just pick one and change it — let me know which direction you want and I'll implement it.

Raw backend error shown to the user

Pre-existing, not touched
Groups list, right under the "Axis" wordmark, on first load

Saw this appear once during testing:

{"code":"PGRST303","details":null,"hint":null,"message":"JWT issued at future"}

This is the clock-skew auth rejection your CLAUDE.md already documents as a known transient issue. It surfaces because BaseViewModel.RunSafeAsync sets ErrorMessage = ex.Message directly — a deliberate simple pattern per your notes, not a bug I'm flagging as broken. Just noting that a real user hitting this transient failure sees raw JSON instead of a friendly message, which is worth a look eventually.

Stacked avatar initials read as dense/cramped

Minor, already partly improved
GroupsPage.xaml, member-avatar row on each group card

The overlapping avatar stack (negative spacing, by design — same pattern Splitwise/Tricount use) shows initials like "OA DR CR ML" tightly packed together. It's legible but dense at a glance, especially in a 5-member group. I already grew these from 18px→22px earlier in the review pass; further improvement (more spacing, or capping visible avatars with a "+N" overflow badge for large groups) is a polish item rather than a defect.
